# KNOWN_ISSUES.md

Format: one entry per issue. State, impact, and whether it blocks a gate.

---
- Locked vs. open doors render with the same brown tile color (no visual distinction). Cosmetic only; doesn't block the P0 gate. Revisit in P1.2 (room templates/transitions) or the P1.10 game-feel pass.
- `tools/simulate.mjs` currently covers a P0-scoped subset of CLAUDE.md §5 (a)/(b)/(c): the 3 existing enemies alone, a kitchen-sink combat scenario, and a bot clearing 20 seeded single-room encounters. Full scope (every boss through its phases, every item at once, 20 seeded full floor runs) needs bosses (P1.8), items (P1.4), and floor generation (P1.1) to exist first — expand simulate.mjs as each lands.
- Wall tiles (`#15151a`) are close in value to the page/canvas background (`#0a0a0d`/`#111`), making room boundaries low-contrast. Cosmetic; still unaddressed after the P1.10 game-feel pass (that pass focused on knockback/hitstop/head-body-facing/the floor-traversal simulate gate) — revisit whenever a renderer/palette pass happens next.
- CLAUDE.md §7's doc set (README.md, GAME_DESIGN.md, TECHNICAL_ARCHITECTURE.md, RESEARCH.md, MODDING_GUIDE.md, ITEM_CREATION_GUIDE.md, CHARACTER_CREATION_GUIDE.md, ENEMY_CREATION_GUIDE.md, DEVELOPMENT_ROADMAP.md) doesn't exist yet — no prior session (P0.1 through P1.6) created them despite completing the tiers those docs are meant to describe. Not blocking any gate so far since PROGRESS.md's own P3.8 ("All docs complete and accurate") is the dedicated gate for this; flagging so it isn't forgotten and P3.8 doesn't turn into an 8-document cold start.
- Shop item price tags/sale sign (P1.6, src/render/renderer.js) use the same canvas-text approach as the item banner but haven't been visually confirmed via a shop-room screenshot (the smoke test's seeded run didn't land in a shop room). Logic is covered by tests/systems-shop.test.mjs; worth an eyeball check next time a run happens to reach a shop.
- The melee weapon type's ctx (weapons.js's fireMelee, called from player.js's updatePlayer) doesn't carry `player`/`playerHealth`, so killing an `exploder`-behavior enemy with melee fires the explosion event but skips the player-damage part of it (bombs/tears/nova all pass the full ctx and work correctly). Melee isn't granted by any item yet, so this isn't reachable in practice; thread playerHealth into updatePlayer's ctx if/when an item grants the melee weapon type.
- P1.8's boss-room/trapdoor/floor-advance wiring hasn't been visually confirmed in the browser (smoke test's seeded run never reaches a boss room on floor 1, since boss rooms sit at the farthest dead end). Logic is covered by tests/systems-bosses.test.mjs + tests/systems-bossPatterns.test.mjs and the simulate gate's per-boss phase-cycling check; worth a manual playthrough (or a debug `nextfloor`/`tp` console command once P3.3 exists) to eyeball the HP bar, telegraphs, and trapdoor.
- `advanceFloor()` (main.js) is a plain cut to the next floor with no transition visual (no fade, unlike the slide between rooms). Worth revisiting in the P1.10 game-feel pass.
- The death screen (src/ui/screens.js's drawDeathScreen) was verified by code inspection and the smoke test's "zero console errors" check, not an actual eyeballed screenshot — forcing an in-browser player death wasn't practical to script quickly in this session. The menu and pause overlays *were* visually confirmed via a one-off Playwright screenshot. Worth a manual look next time a run actually ends in death during testing.
- Floors beyond stage 4 (past chapters 1-2's authored content) fall back to reusing chapter 1/2 enemy/boss pools and palette rather than anything new — expected and intentional until P2.8 adds chapters 3-4 and a final chapter; not a bug, just the edge of current content.
- The HUD is missing several elements CLAUDE.md §3 calls for: coins/bombs/keys counts, the active item's charge bar, and the consumable (card/pill) slot. Only hearts and (as of P2.1) the trinket slot are drawn. Not blocking any gate so far (the underlying Currency/ItemInventory state all exists and is unit-tested; it's purely a rendering gap) — worth a dedicated HUD pass before P2's gate, since P2.2's consumable slot will add yet another missing element otherwise.
